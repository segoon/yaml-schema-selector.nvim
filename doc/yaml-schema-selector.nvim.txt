1. INTRODUCTION                                    *yaml-schema-selector-intro*

yaml-schema-selector.nvim picks the JSON Schema `yaml-language-server` uses
for a buffer by calling a Lua function you provide, instead of relying only
on static glob patterns, a modeline, or the SchemaStore catalog.

It works by registering as the server's custom schema provider: for every
YAML document the server resolves, it asks the client (this plugin) which
schema applies, and your answer wins over `yaml.schemas`, the SchemaStore
catalog, and `json/schemaAssociations` associations.

This plugin never starts or configures `yaml-language-server` itself. It
only layers a handler onto an already-running client.

==============================================================================
2. REQUIREMENTS                              *yaml-schema-selector-requirements*

  - Neovim >= 0.11
  - `yaml-language-server`, started and attached to the buffer however you
    normally do that (e.g. `nvim-lspconfig`'s `yamlls`, or manually with
    |vim.lsp.enable()| / |vim.lsp.start()|)
  - The `yaml` treesitter parser (`:TSInstall yaml`), only required if a
    registered selector calls `ctx.yaml()` / `ctx.yaml_documents()`
  - For the built-in C35 selector only: `arc`, `ya`, and the Python
    environment provided by `ya tool tt python`

==============================================================================
3. SETUP                                            *yaml-schema-selector-setup*

`setup()` configures the plugin's link to the language server; it does not
pick any schemas itself.

>lua
    require("yaml-schema-selector").setup({
      server_name = "yamlls", -- name of the LSP client to layer onto (default)

      schemas = {
        gh_workflow = "https://json.schemastore.org/github-workflow.json",
        k8s = "kubernetes",             -- yaml-language-server's own k8s handling
        house = "./schemas/house.json", -- resolved relative to root_dir
      },

      max_parse_bytes = 1024 * 1024, -- ctx.yaml() gives up above this size
    })
<
Schema selection is done entirely through |yaml-schema-selector.register()|
-- `setup()` has no `select` option. This keeps the two concerns apart:
`setup()` is called once, for yourself; `register()` can be called by any
plugin, including your own config, at any time, without needing to know
whether `setup()` has run yet.

4. REGISTERING SELECTORS                        *yaml-schema-selector-register*

>lua
    require("yaml-schema-selector").register({
      name = "k8s",     -- unique id; re-registering the same name replaces it
      priority = 50,     -- higher runs first; ties broken by registration
                         -- order (default: 50)

      -- Full form: gets the whole ctx, decides everything itself.
      select = function(ctx)
        local doc = ctx.yaml()
        if doc and doc.apiVersion and doc.kind then
          return "k8s"
        end
        return nil -- no opinion; falls through to the next registration
      end,
    })

    require("yaml-schema-selector").register({
      name = "gh_workflow",
      -- Short form: a predicate plus a fixed (or computed) answer.
      matcher = function(ctx)
        return ctx.path:match("/%.github/workflows/") ~= nil
      end,
      schema = "gh_workflow", -- or a function(ctx) -> selection

      -- Registrations may also contribute their own aliases, merged into
      -- the shared alias table (setup()'s `schemas` always wins on conflict).
      schemas = { gh_workflow = "https://json.schemastore.org/github-workflow.json" },
    })
<
Give either `select`, or `matcher` + `schema` -- not both. A registration
with only `schemas` (no `select`/`matcher`) is also valid, for plugins that
just want to contribute aliases.

`require("yaml-schema-selector").unregister(name)` removes a registration; a
no-op if it was never registered.

Resolution runs every registration in priority order (highest first, ties by
registration order) and uses the first one that returns non-nil; a `select`
that returns nil, or a `matcher` that doesn't match, falls through to the
next registration, and eventually to the server's own resolution chain if
nothing matches.

`select`/`matcher` must be synchronous: they run inside the handler for the
server's `custom/schema/request`, which cannot be answered asynchronously.

A `select`, or the `schema` given alongside a `matcher`, may return:
  - `nil`, meaning "no opinion" (falls through, see above);
  - a single value; or
  - a list of values.

Each value is one of:
  - a key of the merged `schemas` table (substituted exactly once — no alias
    chains, so cycles are impossible);
  - a full URI (`https://...`, `file://...`);
  - a filesystem path, absolute, `~`-relative, or relative to `root_dir`;
  - the literal string `"kubernetes"`.

5. AUTODISCOVERY                                  *yaml-schema-selector-discover*

Any file matching `lua/yaml-schema-selector/schemas/**/*.lua` on
'runtimepath' is registered automatically -- no explicit `register()` call
needed. This lets a plugin ship its own selector for its own file format
bundled inside its own repo, the same way lazy.nvim discovers
`lua/plugins/*.lua`:

>lua
    -- lua/yaml-schema-selector/schemas/kubernetes.lua
    return {
      matcher = function(ctx)
        return ctx.filename:match("%.k8s%.ya?ml$") ~= nil
      end,
      schema = "kubernetes",
    }
<
Each file returns a single |yaml-schema-selector-register| table, or a list
of them. If `name` is omitted it defaults to the file's path relative to
`schemas/`, with `/` becoming `.` and `.lua` stripped (e.g.
`schemas/kubernetes.lua` -> `"kubernetes"`, `schemas/helm/values.lua` ->
`"helm.values"`); unnamed entries in a list returned from one file get `#1`,
`#2`, ... suffixed onto that default.

`setup()` runs discovery once, unless `discover = false` is set.
`require("yaml-schema-selector").discover()` re-scans manually (e.g. after
`:so %` during development, or after a plugin manager adds more plugins to
'runtimepath'); it also unregisters any previously discovered entry whose
source file has since disappeared, without touching entries registered
directly via `register()`. See |yaml-schema-selector-health| for how to
inspect which selectors came from autodiscovery, and any file that failed to
load.

If two 'runtimepath' entries provide the same relative path (e.g. two
plugins both ship `schemas/foo.lua`), only the first one found is loaded;
the second is reported as an error (visible via |:checkhealth|) rather than
silently overriding or being silently skipped.

BUILT-IN SELECTORS

The plugin ships content-based selectors for OpenAPI 3.x and Swagger 2.0.
It also recognizes Arcadia C35 files named exactly `codegen-module.yaml` and
builds their schema from the `codegen-plugin.yaml` files referenced by the
module's top-level plugin paths.

The C35 generator runs asynchronously through `ya tool tt python`, using the
module's directory as the working directory so `arc root` selects the right
checkout. Until generation completes, selection falls through to the next
selector and then to the server. Successful schemas are stored as
content-addressed JSON files below Neovim's cache directory, after which the
server is asked to resolve schemas again. Saving `codegen-module.yaml`
invalidates and regenerates its schema. To pick up a change made only to a
referenced `codegen-plugin.yaml`, use |:YamlSchemaRefresh| or save the module
file again.

6. CONTEXT                                        *yaml-schema-selector-context*

The table passed to `select`/`matcher`:

    uri                 document URI as sent by the server
    path                absolute filesystem path
    filename            basename of `path`
    bufnr               buffer handle, or `nil` if not loaded
    filetype            buffer filetype, or `nil` if not loaded
    root_dir            root directory of the LSP client, or `nil`
    client_id           id of the `yamlls` client
    schemas             the merged alias table (setup()'s `schemas` +
                        every registration's `schemas`)
    lines(n?)           first `n` lines (default: all); lazy
    yaml()              first YAML document as a Lua value, or `nil`; lazy
    yaml_documents()    all `---`-separated documents as Lua values; lazy

`yaml()` / `yaml_documents()` parse with the `yaml` treesitter grammar. This
is a lightweight parse, not a full YAML 1.2 implementation:
  - a key whose value is null or empty (`foo:`, `foo: ~`, `foo: null`) is
    left out of the resulting table entirely, so `doc.foo and doc.foo.bar`
    guards behave as expected;
  - anchors, aliases, and merge keys (`<<:`) are not resolved;
  - parsing is skipped, and these functions return `nil` / `{}`, for buffers
    over `max_parse_bytes`, and when the `yaml` parser isn't installed.

Parsing is memoized per buffer and change, so calling `yaml()` from a
registered selector costs nothing on repeated validations of an unchanged
buffer, and nothing at all if it's never called.

7. COMMANDS                                      *yaml-schema-selector-commands*

                                                          *:YamlSchemaRefresh*
:YamlSchemaRefresh
    Ask the server to re-resolve the schema for every open document. Useful
    when something a registered selector depends on changed outside of
    Neovim (e.g. a file it reads from disk).

8. LUA API                                            *yaml-schema-selector-api*

require("yaml-schema-selector").setup({opts})       *yaml-schema-selector.setup()*
    Configure the plugin and attach to any running (or future) client named
    `opts.server_name`. See |yaml-schema-selector-setup|.

require("yaml-schema-selector").register({spec})  *yaml-schema-selector.register()*
    Register a schema selector, a set of schema aliases, or both. Safe to
    call at any time, independent of `setup()`. See
    |yaml-schema-selector-register|.

require("yaml-schema-selector").unregister({name}) *yaml-schema-selector.unregister()*
    Remove a previously registered entry, if any. A no-op otherwise.

require("yaml-schema-selector").discover()         *yaml-schema-selector.discover()*
    Re-scan 'runtimepath' for lua/yaml-schema-selector/schemas/**/*.lua files
    and (re-)register what they return. Called automatically by `setup()`
    when `opts.discover` is true (the default). See
    |yaml-schema-selector-discover|.

require("yaml-schema-selector").refresh()          *yaml-schema-selector.refresh()*
    Equivalent of |:YamlSchemaRefresh|.

require("yaml-schema-selector").resolve({bufnr})   *yaml-schema-selector.resolve()*
    Run every registration for {bufnr} (default: current buffer) and return
    the normalized schema value(s) that would be sent to the server, or
    `nil`. Does not talk to the server; a debugging aid, and the basis of
    |:checkhealth|.

==============================================================================
9. HOW IT WORKS                                *yaml-schema-selector-internals*

On `setup()`, and on every `LspAttach` of a client named `server_name`
(`yamlls` by default), the plugin:

  1. installs a handler for the server's `custom/schema/request`;
  2. sends the `yaml/registerCustomSchemaRequest` notification, which makes
     the server register the client as its schema provider;
  3. sends `workspace/didChangeConfiguration`, so documents opened before
     registration get re-validated with the provider in the loop.

Schema resolution precedence, per the server's own documentation, highest
first: modeline > inline `$schema:` > custom provider (this plugin) >
`yaml.disableSchemaDetection` > `yaml.schemas` > `json/schemaAssociations` >
SchemaStore.

==============================================================================
10. HEALTH CHECK                                    *yaml-schema-selector-health*

`:checkhealth yaml-schema-selector` reports:
  - Neovim version support;
  - whether `setup()` has been called;
  - whether the `yaml` treesitter parser is available;
  - whether `yaml-language-server` is on `$PATH`;
  - whether a client named `server_name` is running, and whether the schema
    provider handler is installed on it;
  - what resolution returns for the current buffer;
  - which registered selectors were contributed by autodiscovery, and
    whether any autodiscovered file failed to load (see
    |yaml-schema-selector-discover|).
